# Limitation 局限说明（README 同步引用，面试重点）

1. 复杂多表关联、非标业务口径，仍需人工持续维护指标词典；**新增指标必须入库注册**后才能查询。
2. 无法 100% 拦截所有畸形 SQL，采用「规则 + 语义」双层兜底，不存在绝对安全。
3. 不替代数据库本身权限，数据库底层权限仍需配置；本层是上层业务风控网关。
4. 无法自动理解未注册的新业务指标；未注册指标默认被安全拦截（开启 LLM 候选后仍需过安全网关）。
5. 结果校验依赖人工配置阈值（指标的 `max_value`），阈值需业务人员配置。
6. 语义解析基于「名称/别名最长命中 + 术语词典」的确定性匹配，对复杂长问句、同义词覆盖有限；
   更自然的语义理解需引入 LLM（当前为可选兜底）。
7. 内置 SQLite（POC 零配置、自动播种）与 PostgreSQL/MySQL 数仓适配器（可选依赖 psycopg / PyMySQL）；Oracle/达梦等更多数仓方言适配在迭代路线中。
8. 面向内部业务查询 / POC 验证场景，未做超大并发、分布式设计。
