# PRD｜semantic-sql-guard 语义问数安全网关

## 1. 产品定位
面向数据中台、BI 智能问数、敏感指标查询场景，解决 Text2SQL 三大投产风险：
**口径不一致、越权查询、幻觉高危 SQL**。作为上层防护网关，叠加在 Text2SQL 服务之上，
实现「语义对齐 + SQL 静态安全校验 + 行级权限 + 结果风控」。核心原则：**先控权限、再做查询**。

## 2. 用户角色
- FDE 交付：落地央企智能问数、纪检资金风控、经营指标查询
- 数据产品：维护指标注册表、业务术语词典
- 安全审计：审计 SQL 查询、拦截高危访问
- 业务用户：自然语言查询指标，在权限范围内获取数据

## 3. 用户故事
1. 作为数据产品，我需要维护指标注册表、业务术语词典，统一业务口径，减少模型语义幻觉。
2. 作为安全负责人，我需要拦截访问敏感表、高危 SQL 语句（drop、alter 等）。
3. 作为交付，我需要在行级权限上做过滤，用户只能看到自己权限范围内的数据。
4. 作为系统，查询结果数值异常波动/为空时自动拦截或标记，拒绝返回可疑脏数据。
5. 作为运维，我需要全链路审计：原始问句、匹配语义、生成 SQL、执行结果、调用人、时间。

## 4. 核心功能清单
1. 业务术语词典 + 指标注册表管理（`data/registry.yaml`）
2. 自然语言语义解析，匹配注册指标 + 提取维度值
3. 确定性 SQL 模板生成（已注册指标，口径锁定）
4. SQL 静态安全校验：仅 `SELECT`、拦截多语句与高危语法、表白名单、敏感表按角色拦截
5. 行级权限过滤：在 SQL 生成阶段注入角色可见行条件
6. 结果异常校验：空结果、聚合 NULL、数值超限、行数过多
7. 全链路 SQL 审计日志（JSONL 落盘 + 内存环形缓冲）
8. 可选 LLM 候选 SQL（未注册指标兜底，默认关闭，仍须过安全网关）

## 5. 非功能需求
1. 作为上层网关，不替代数据库原生权限，是叠加业务风控层。
2. 审计日志完整留存，支持查询导出。
3. 支持 SQLite（POC 零配置、自动播种样例数据）与 PostgreSQL/MySQL 数仓（可选依赖 psycopg / PyMySQL）。
4. 支持私有化内网部署（docker-compose 离线拉起）。

## 6. 验收标准（v0.1，本仓库当前）
1. `docker compose up -d` 或 `make run` 可启动；`make demo` 可跑全链路。
2. 指标词典注册、术语匹配生效（`make test` 全绿）。
3. 高危 SQL、敏感表、未注册指标均被拦截。
4. 行级权限按角色生效，越权范围外返回空结果。
5. 审计日志完整记录查询链路。

## 7. 迭代路线
- v0.1：词典、指标注册、SQL 拦截、行级权限、审计、结果校验（当前）
- v0.2：结果波动趋势校验、慢查询熔断、查询限流
- v0.3：badcase 自动回流、对接 enterprise-ai-eval-harness 评测
- v0.4：可视化语义配置后台、PostgreSQL/MySQL 数仓适配
